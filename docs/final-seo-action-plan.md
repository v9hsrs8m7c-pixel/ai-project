## 1. 战略顺序（不变，强化）

```
真实搜索需求 → 数据验证主题 → 生成对应原创游戏 → 每页带 SEO 文本 → 上线收录
     → Search Console 真实数据闭环 → 达到一定流量 → 接变现（Gamezop / AdSense / 开发者分成）
```
**绝不**为凑数量无目标生成游戏。已生成的 8 个经典游戏（2048/ Snake/ Tetris 等）属"高确定性安全牌"，保留为首测资产；后续扩充必须走数据验证。

## 2. 冷启动关键词研究（修复 R1/R2/R3）

新站无 GSC 数据，前 4–8 周只能靠第三方信号 bootstrap：

- **工具（免费优先）**：Google Keyword Planner（免费层）、Google Trends、手动 SERP 抽查、AlsoAsked、AnswerThePublic（免费额度）、Reddit/游戏论坛挖掘真实提问。
- **地理**：主 **US**，次 **UK**；所有量/难度均按指定 country 读取，不混全球。
- **数值门槛（新站适用）**：
  - 主力主题：KD ≤ 15，月搜索量 100–20,000。
  - 长尾候选：月搜索量 10–500，KD 不限（长尾本就低竞争）。
  - 头部大词（"online games"级）仅作战略方向，**不进首批**。
- **输出**：约 30 个核心主题 + 约 100 个长尾候选（沿用 Doc1 规模，但来源可落地）。
- **字段**（沿用 Doc1 表格）：关键词 / 搜索意图 / 来源 / 热度趋势 / 竞争线索 / SERP 类型 / 目标页面 / 对应游戏主题。

## 3. 技术 SEO 地基（修复 R4/R6，当前站点缺失 → P0）

当前 `ai-project` **尚无**以下项，须优先补齐（Next.js 16 实现）：

1. `sitemap.xml` 动态生成（包含所有游戏/分类/专题/信任页）。
2. `robots.txt`（允许抓取，指向 sitemap）。
3. `canonical` 标签（防重复内容）。
4. **结构化数据**：游戏页加 `VideoGame` / `SoftwareApplication` JSON-LD（name/description/genre/url），信任页加 `Organization`。
5. **Open Graph / Twitter Card**（社交分享与预览）。
6. **移动端 + Core Web Vitals 预算**：自托管 canvas 游戏**懒加载 + 预连接**，首屏不阻塞 LCP；监控 CLS/LCP/INP。
7. **内部链接**：分类 hub 页为中心，游戏页互链 + 相关推荐模块（见 §5）。

> 验证：上线后提交 sitemap 到 Search Console，观察索引覆盖率。

---

## 4. 游戏页内容模板（修复 R5：解决 iframe 不可索引）

游戏本体是交互 canvas，Google 不索引。每游戏详情页必须有**独立原创文本**才能排名：

- 每页 **≥300 词**原创文本：游戏名 + 简介 + 玩法说明 + 操作方式 + FAQ（3–5 条）+ 攻略/提示 + 相关推荐。
- 文本与游戏一一对应、不抄袭第三方品牌/文案/美术（IP 合规，也是平台审核拒因）。
- 由 WorkBuddy 按 §2 验证过的主题生成草稿，人工过目后发布。
- 数据字段沉淀在结构化数据文件（见 §8），便于复用与未来迁移 CMS。

---

## 5. 页面结构与内部链接

- **首页**：定位 + 核心分类入口 + 推荐/热门。
- **分类 hub 页**：Puzzle / Arcade / IO / Action…（以 §2 结果定），作为内链枢纽。
- **游戏详情页**：游戏 + §4 文本 + 相关推荐。
- **专题页**：围绕明确搜索意图的一组游戏（如"no wifi games""brain games for adults"）。
- **信任页**：About / Contact / Privacy / Terms / 404。
- **内链策略**：分类 hub 链向所属游戏；游戏页底部"相关推荐"互链；正文中 context 链接到相关游戏/分类。

---

## 6. 发布节奏与淘汰机制（沿用 Doc2，补节奏）

- **节奏**：首月每周上线 5–8 个"已验证主题"游戏（含 §4 文本）；之后按 GSC 真实查询词扩/优/淘。
- **淘汰**（沿用 Doc2）：新游戏先观察、不因短期无流量删；长期无曝光无访问且无线略价值→淘汰候选；高曝光低 CTR→先优化标题/描述/匹配度，不删。

---

## 7. 变现阶段与触发（补具体数字）

- 当前不把收入作上线前置。
- **触发 A**：≈30 个已收录页面 + 约 500 sessions/月 → 申请 **Gamezop partner**（最轻门槛嵌入分成）。
- **触发 B**：≈1,000 sessions/月 + 稳定收录 → 接 **Google AdSense**（站内广告，第二收益线）。
- **触发 C**：自研游戏达量 → 以**开发者身份**投 GD / CrazyGames 拿分成。
- 顺序：先内容资产与自然流量，再变现。

---

## 8. CMS 后台：延后到第三阶段（修复 R7）

- **当前判断**：前 ~100 个游戏，内容定义在结构化数据文件 + 套用 §4 模板即可，无需后台。自建完整 CMS（DB+鉴权+admin+多站点）是架构级重建，拖延流量工作，**不是上线前置条件**。
- **当前替代方案**：游戏/页面内容用结构化数据文件管理；提供内容模板与少量辅助脚本；保持"改文件→构建→上线"的轻量流程。
- **未来（第三阶段）触发**：内容规模/编辑人数上来、确需免代码运营时，再上 headless CMS（Decap/Sanity 等）或自建；数据模型预留 **Site → Category → Game → Page/SEO** 以便多站点复用。
- **明确**：本阶段不启动 CMS 开发。
